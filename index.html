?Why do we need knowledge graphs at all?

An agent only knows the code it can see, and across repos it sees almost nothing

● In view: 1 repo
● The answers live out there
✗ Search: too many hits
✗ Read it all: doesn't fit
?So what must be prepared for the agent in advance?

A knowledge graph computes the relationships ahead of time, so the agent can ask instead of read

Without a graph · read
Open, read, guess, repeat
With a graph · ask
One call, one answer
Nodes files · functions · symbols · API fields
Edges calls · imports · references · uses
Built once per repo · linked across the org

?Are all code graphs the same?

No: there are three kinds, each built from a different source of truth

Syntax graph

Built bya parser (tree-sitter)Readsthe text of each fileNeedsnothing else

Compiler index

Built bythe compiler (SCIP)Readsthe whole program, typedNeedscode that builds

Contract graph

Built byan API extractorReadsschemas, queries, eventsNeedsdeclared APIs
Different source → different truth
