# Project rules (knowledge-graphs-toy)

A toy organisation (4 tiny repos) for showing where each kind of code graph — syntax graph (Graphify),
compiler index (SCIP), contract graph — succeeds and fails, with automatic checks. Start with `README.md`.

## Hard rules

- **Everything stays in this folder** (one exception: the credential, below). No global or user-level installs or changes (no `~/.claude`, `~/.cache`,
  global npm/pip). Run tools through `bin/sandbox` (all `bin/` scripts already do). Check with
  `bin/check-containment snapshot <a>` / `compare <a> <b>`.
- **Claude subscription only.** Never use an API key; `bin/sandbox` refuses `ANTHROPIC_API_KEY`. The token lives outside the
  project in `~/.config/claude/temp_creds/knowledge-graphs-toy.env` (override with `KG_SECRETS_FILE`) — never print it
  and never copy it into the project.
- **Agent runs use Haiku** (`claude-haiku-5-5`); the grader is Opus with no tools.
- **No Claude attribution** anywhere in git or GitHub.

## How things fit

- `./setup.sh` sets up a fresh clone (macOS or Linux): pinned tools into `tools/`, the sign-in, `bin/setup`, `bin/check`.
  Version pins: `tools/versions.env`, `tools/requirements-*.txt`, the package-lock files. Scripts must run on macOS too:
  bash 3.2, BSD tools (no `find -printf`, `sed -i`, `getent`, `readlink -f`).
- `toy-src/` is the source of truth for the repos. `worlds/` is generated by `bin/setup` — never edit it by hand;
  change `toy-src/` or `org.json` (worlds, regexes) and re-run `bin/setup`.
- `scenarios/*.json` hold each question, world, workspace, answer key, expected result per configuration, lesson,
  deterministic tool checks and optional `read_limit`. `SCENARIOS.md` and the measured badges in `core-3x3.html`
  (between `// BEGIN measured` and `// END measured`) are generated from them and `results/` by `bin/make-docs`.
- `conditions/` (the configurations) is generated by `bin/make-templates`; edit the script, not the folders.
- `graphs/server.py` is the shared `org` MCP server (search, read, syntax graph, SCIP, contract graph; central or
  federated). `graphs/scip_lib.py` and `graphs/contract_lib.py` do the per-repo extraction and the linking.

## After any change

1. `bin/setup` (if `toy-src/` or `org.json` changed) — about 25 s.
2. `bin/check` — must print ALL CHECKS PASSED (no model calls).
3. `bin/verify [scenario ...] --reps 3` — Haiku; every cell must PASS against its expectation.
4. `bin/make-docs` — refresh SCENARIOS.md and the core-3x3.html badges.
